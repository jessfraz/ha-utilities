# Utilities

Read-only utility bills, balances, collection events, and meter intervals for
Home Assistant. Waste Management and Bayou are native adapters; SQLite keeps
the reconciled local read model used by the dashboard, CLI, and Assist.

## Run

In Home Assistant, add the Bayou API key in the app's Configuration options,
then open **Settings → Connect utility**. Choose the utility, review the Bayou
workspace's data and billing settings, and sign in on Bayou's hosted page.
Return to select the accounts and meters for this deployment. Setup and
selected bindings are saved in SQLite. Utility passwords stay with Bayou.
Bills cover the whole selected utility account. Meter selection limits usage
intervals, not account bill totals or Bayou's workspace charges.

Waste Management uses explicit account and service bindings and its WM-issued
token and ClientId. Native installations can use
[the fictional TOML example](config/example.toml) with runtime credential-file
paths. Keep credentials in 1Password and runtime storage, never source control.

```sh
utilities --config /data/config.toml --database /data/utilities.sqlite3
ha-utilities --token-file /data/api-token providers list
ha-utilities --token-file /data/api-token bills list --limit 25 --json
fetch-home-assistant ha-utilities --transport home-assistant summary --json
```

HA transport uses `HOME_ASSISTANT_URL` and `HOME_ASSISTANT_TOKEN`. Native uses
`UTILITIES_URL` and `UTILITIES_TOKEN_FILE`. Explicit `--url` and `--token-file`
override those settings; `ha` remains a transport alias.

The server creates a private API-token file on first startup. Native clients
use bearer authentication; the browser uses an HTTP-only session. The HA app
uses admin-only Supervisor ingress. `/openapi.json` is generated by Dropshot
from the Rust types, also available with `utilities --openapi PATH`.

Add this repository to the HA app store and install the Utilities integration
from Marketplace, or extract the release's `utilities.zip` into
`custom_components/utilities`. It supplies a collection calendar, sensors,
guarded Energy statistics, redacted diagnostics, Repairs, and explicitly exposed
read-only Assist tools. Version Repairs remain available when the first data
refresh fails. Native HA cold backups own recovery.

[Provider contracts and limits](PROVIDERS.md) explain coverage. Sync only reads
data. Hosted setup creates a Bayou customer after explicit consent; it does not
open a new utility account, pay bills, or book collections.
Provider access is not established merely by installing this app. Empty,
partial, unavailable, and stale data remain distinguishable.

## Connect from the CLI

```sh
ha-utilities connections utilities
ha-utilities connections start --utility speculoos_power --accept-provider-settings
ha-utilities connections list
ha-utilities connections authorize CONNECTION_ID
ha-utilities connections refresh CONNECTION_ID
ha-utilities connections bind CONNECTION_ID --account PROVIDER_ACCOUNT --meter PROVIDER_METER
```

`speculoos_power` is Bayou's fictional utility. Choose a real ID from
`connections utilities`. `authorize` returns a private, temporary sign-in URL;
open it locally and keep it out of logs. Setup does not select accounts or
meters automatically. Use `--meter` more than once for multiple meters.

If `start` cannot confirm its result, its error includes `request_id`. Retry
with the same `--request-id`, or use `connections list` to find saved setup.
`connections resume CONNECTION_ID` checks an interrupted request before
continuing. Restarting the app does not blindly repeat an uncertain create.

`GET /v1/providers/bayou/utilities` lists supported utilities.
`GET /v1/connections` lists saved setup; `POST /v1/connections` starts it.
`GET /v1/connections/{id}` reads one connection. A saved connection has
`refresh`, `resume`, and `bind` POST actions and an explicit `authorization`
GET action. The Home Assistant bridge requires an administrator for connection
setup and temporary links. Ordinary read-only Assist tools cannot create them.

## Sync

The first sync reads all history available to the connected account. After
that, Utilities checks the previous seven completed UTC days once per day. A
manual sync starts with the past three calendar months filled in. Each live
connection's Settings dialog contains its sync controls and progress. Choose
**Sync all available history** there to read the full provider history again.

Repeated reads update matching bills and meter intervals in place. A Home
Assistant Repair appears after 40 days without new provider records, even if
the sync itself has been running. New data clears the Repair.

```sh
ha-utilities sync list
ha-utilities sync request --account ACCOUNT_ID --from 2026-08-01 --to 2026-11-01
ha-utilities sync all --account ACCOUNT_ID
```

`POST /v1/sync` accepts either `account`, `from`, and `to`, or `account` and
`"range": "all"`. `GET /v1/sync` returns the latest job for each bound account.

## Import billing records

Extract bill details, charge lines, payments, and measurements into a typed
bundle before import. Place the source files and a `manifest.json` in one
private directory. The manifest contains `documents` entries with `sha256`
and relative `path`, plus an `imports` array of `ImportRequest` objects
from the generated OpenAPI schema.

```sh
ha-utilities ingest ./bundle --check --json
fetch-home-assistant ha-utilities --transport home-assistant ingest ./bundle --json
```

The first command checks the whole bundle locally. The import uploads each
verified source by digest, then commits each account batch. Keep account and
service IDs and printed record references stable across runs. A replay
reports zero new records. A conflicting fact requires review or an explicit
replacement against the current record revision.

To combine duplicate manual accounts, prepare an
`ImportAccountConsolidation` JSON request with the existing `source` and
`target` import-account identities, `currency`, `expected_source_records`,
and `expected_target_records`. Both accounts must use manual import and have
the same issuer and cutoff.

```sh
fetch-home-assistant ha-utilities --transport home-assistant consolidate-imports ./consolidation.json --json
```

`POST /v1/imports/consolidate` moves all source ownership in one transaction.
The operation preserves record IDs, revisions, service IDs, documents, and
original provider-account fingerprints. Keep the original two intake requests
in future bundles. Each original account ID routes to the surviving account,
retaining its own financial identity and replay receipts. Repeating the exact
consolidation request returns its saved receipt. Account filters use the
surviving ID, and existing bill URLs continue to work.

To remove one imported bill, use its bill ID, original intake account ID, and
current revision. `bills get BILL_ID --json` returns the bill and its revision.

```sh
fetch-home-assistant ha-utilities --transport home-assistant purge-imported-bill BILL_ID \
  --origin-id ORIGINAL_ACCOUNT_ID --expected-revision REVISION --json
```

`POST /v1/imports/bills/{id}/purge` accepts an `ImportBillPurge` request. It
removes the bill, explicitly linked records, and documents used only by that
family. A changed revision rejects the whole operation. Repeating the same
request is a no-op; replaying the removed bill's old intake is rejected.
Surviving records and shared source documents keep their identities and bytes.

Add `--remove-unused-service SERVICE_ID` for each service to retire. Removal
requires that the original intake owns the service and no surviving records
or projections use it. The native API requires the owner credential; the HA
bridge requires an administrator.

The native owner API can also remove an entire import-only account with
`POST /v1/imports/accounts/{id}/purge`. Confirm the exact `provider` and
`expected_records` count in the request. The transaction removes the account,
its records, and source files referenced only by that account.

The overview shows reported charges and quantities by bill issue month.
Open a bill for its printed totals, itemized rates, linked payments, and
source downloads. Import is available to the native owner and HA admins.
